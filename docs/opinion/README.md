# The opinion log

A standalone record of what this product actually was at a point in time, in
the builder's own words, written as an assessment rather than a changelog.

Nothing in here is imported by code, published to the site, or read by any
build step. It exists so that when the product is being marketed, or when a
decision has to be revisited, there is an honest account of where it stood and
what was wrong with it at each stage.

Each entry is dated and numbered. A new one is written whenever a substantial
assessment is asked for, and **old entries are never edited**. The point is the
gap between them.

## How to read these

They are deliberately unflattering. An opinion that lists only what works is
not worth keeping, because the value of this log is entirely in the parts that
turned out to be right about the problems.

## When to write a new one

- A substantial capability lands and the shape of the product changes
- Before a pricing or positioning decision
- Before a launch
- Whenever the question "is this actually good yet" is asked seriously
